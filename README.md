# 个人学术主页模板

单栏、简历式排版的学术主页模板，无需构建工具，可直接部署到 GitHub Pages。

页面采用**内容与排版分离**的结构：

- `index.html` —— 只负责排版：CSS 样式 + 读取并渲染 `content.md` 的脚本，不含任何正文内容。
- `content.md` —— 存放全部实际内容。文件开头的 YAML frontmatter（`---` 包裹的部分）描述头部信息，其后的 Markdown 正文按二级标题（`##`）划分各区块。
- `preview.cmd` —— 本地预览启动器，双击即可（见下文"本地预览"）。
- `assets/` —— 图片等素材，目前用于放置个人照片。

> 因为内容通过 `fetch` 读取，**不能直接双击打开 `index.html`**（浏览器禁止 `file://` 页面读取本地文件），需通过本地服务器或线上部署访问。若直接打开，页面会给出提示。

## 修改内容

只需编辑 `content.md`，无需改动 `index.html`。

### 1. frontmatter（头部信息）

| 字段 | 说明 |
| --- | --- |
| `page_title` | 浏览器标签页标题。不填则自动用 `name` + `en_name` |
| `description` | 搜索引擎描述。不填则自动取正文第一段 |
| `name` | 页面大标题（中文名） |
| `en_name` | 英文名，显示在大标题右侧 |
| `photo` | 个人照片路径，如 `assets/photo.jpg`；也可填完整网址。留空或删掉此行则不显示照片 |
| `photo_shape` | 照片形状，三选一：`circle` 圆形（默认）/ `rounded` 圆角矩形 / `square` 直角矩形 |
| `title` | 职称，如"助理教授" |
| `affiliation` | 单位，显示在职称下一行 |
| `email` | 邮箱，自动生成 `mailto:` 链接 |
| `links` | 主页链接列表，每项含 `label` 与 `url` |
| `updated` | 最后更新时间，渲染为页脚的"最后更新于 ……。" |
| `footer` | 页脚补充说明，可省略 |

### 2. 正文（Markdown）

- 第一个 `##` 之前的所有段落作为**简介**渲染。
- `## 标题` —— 划分区块；`##` 之后的列表/段落依次排入该区块。
- `#`（一级标题）会被忽略——姓名请写在 frontmatter 的 `name` 里。
- `### 小标题` —— 区块内的次级小标题。

**排版样式由内容结构自动判断，一般不需要手动指定：**

| 写作方式 | 渲染效果 |
| --- | --- |
| 无序列表 `-` | 圆点列表 •（论文、荣誉、教学等都是这个） |
| 无序列表，条目以 `**时间**` 开头 | 时间线排版（左侧时间栏 + 右侧内容） |
| 有序列表 `1.` | 左侧 `[1] [2]` 编号（参考文献观感）；条目里 `*斜体*` 会单独成行，用作期刊/会议信息 |
| 列表项下缩进一层 `- 子项` | 灰字次级说明行（如"导师：××× 教授"） |

一言以蔽之：**`-` 就是圆点列表，`1.` 就是编号列表**，和 Markdown 原本的观感一致。

条目之间可以空行分隔（写长文献时更好读），仍算同一个列表；列表与后续段落之间空行则正常分段。

如需覆盖默认样式，可在标题后加花括号指定样式类，例如：

```markdown
## 研究方向 {.tags}
## 学术服务 {.text-sm}
## 论文 {.pub-list}
```

- 段落类名：`.tags`（灰色无衬线标签行）、`.text-sm`（小一号正文），仅作用于该区块的正文段落。
- 列表类名：`.bullet-list`（圆点列表）、`.timeline`（时间线）、`.pub-list`（`[1]` 编号列表），用于强制指定该区块的列表排版——例如想给一组条目加上编号，写 `## 论文 {.pub-list}` 即可，不必把 `-` 改成 `1.`。这类类名不会被加到正文段落上。

行内支持 `**加粗**`、`*斜体*`、`` `代码` ``、`[文字](链接)`。

### 3. 注释（写了但不上屏的内容）

`content.md` 里可以随手留笔记，页面不会把它们渲染出来：

| 写法 | 位置 | 说明 |
| --- | --- | --- |
| `# 说明` | frontmatter | 整行注释 |
| `name: 许冉 # 姓名` | frontmatter | 值后面的行尾注释；值用 `"引号"` 包起来时，引号内的 `#` 会保留 |
| `<!-- 说明 -->` | 正文任意位置 | 可跨多行，也可夹在一行文字中间 |
| `[//]: # (说明)` | 正文 | 整行注释，带缩进或带 `-` 列表符号也可以，整条会被删掉 |
| `# 说明` | 正文 | 以 `#` 开头的整行（一级标题本来就由 frontmatter 的 `name` 决定，正文里的 `#` 一律忽略） |

两点提醒：

- 正文里未闭合的 `<!--`（忘了写 `-->`）会按 HTML 规范一直隐藏到文件末尾，写注释时记得配对。
- 把某区块的条目全部注释掉时，该区块的 `##` 标题仍会留在页面上（只是下面没有内容）。想整块消失，连标题一起注释即可。

### 4. 照片

把照片文件放进 `assets/` 文件夹，然后在 frontmatter 里写上路径：

```yaml
photo: assets/photo.jpg
photo_shape: square
```

- 支持 `jpg` / `png` / `webp` / `svg`，也可以直接填网上的图片地址。
- 文件名建议用英文或拼音、避免空格。文件夹里有一份 `assets/README.txt` 写着同样的说明。
- **不用自己裁图**：页面会按比例铺满容器、裁掉多余边缘，并优先保留画面顶部（人像构图时头部不会被切到）。
- 三种形状各自带一个接近常见人像的宽高比：`circle` 174×174、`rounded` 174×218、`square` 174×244（5:7，与一寸/二寸证件照一致）。
- 窄屏下照片会自动移到姓名上方并居中，高度按比例缩小。
- `photo` 留空或文件不存在时，照片位置整体消失，页面回到纯文字排版，布局不会错位。

## 更换配色

页面顶部的绿色细线和各标题下方的短下划线是同一强调色 `--accent`，如需更换配色，只需修改 `index.html` 中 `<style>` 开头 `:root` 里的几个变量（`--paper` 背景、`--ink` 文字、`--accent` 强调色等），无需改动其余代码。

## 本地预览

页面通过 `fetch` 读取 `content.md`，而浏览器不允许 `file://` 页面读取本地文件，所以**不能直接双击 `index.html`**，必须经 http 访问。

最简单的方式：**双击 `preview.cmd`**。它会自动找一个可用端口启动本地服务器，并打开浏览器；关闭那个命令行窗口即停止服务。改完 `content.md` 回到浏览器刷新即可看到最新效果。

也可以在命令行里手动启动：

```bash
python -m http.server 8000
# 或
npx serve
```

然后访问 `http://localhost:8000`。

### 两个已知的坑

**其一：`preview.cmd` 的提示文字是英文，文件内容为纯 ASCII。** 这是刻意为之，不是偷懒。cmd.exe 用 ANSI 代码页解析 `.cmd` 文件，若文件以 UTF-8 保存，某个中文字符的字节正好跨在行尾时会把换行符"吃掉"，导致下一行被粘进当前行，报出 `&& was unexpected` 之类莫名其妙的语法错误（`chcp 65001` 也救不了，它只影响控制台输出，不改变 cmd 读文件的方式）。如需改成中文提示，请把该文件另存为 ANSI/GBK 编码。

**其二：Windows 会为自己保留一些端口段。** 用 `netsh int ipv4 show excludedportrange protocol=tcp` 可以看到，比如常见的 `7956-8055`。这类端口即使没有任何程序监听，绑定也会失败（`WinError 10013`）——所以只查"端口是否被占用"是不够的，脚本改用 Python 实际试绑：从 8000 起按 100 递增（保留段通常百来个端口宽），直到找到能绑的端口。**实际端口以窗口里打印的地址为准**，不一定是 8000。

## 部署到 GitHub Pages

### 必须包含的文件

推到仓库根目录的文件（`preview.cmd` 只是本地用的，推不推都行）：

```
index.html     content.md     .nojekyll
README.md      preview.cmd    .gitignore
assets/        照片等素材
```

### `.nojekyll` 是必须的，不能漏

GitHub Pages 默认会用 Jekyll 处理仓库，而 **Jekyll 会把带 YAML frontmatter 的 `.md` 编译成 HTML**。`content.md` 开头正好是 `---`，所以不加这个文件的话它会被编译成 `content.html`，`content.md` 本身在线上不存在 —— 页面里的 `fetch('content.md')` 会 404，打开只能看到一句错误提示。

`.nojekyll` 是个空标记文件（内容无所谓，存在即可），放在仓库根目录就能让 GitHub Pages 原样发布所有文件，`.md` 也就还在了。

### 步骤

1. 仓库名设为 `你的用户名.github.io`（个人主站）或任意名字（项目页面）。
2. 把上述文件放到仓库根目录，commit + push。
3. 打开仓库 **Settings → Pages**，在 "Build and deployment" 中把 Source 设为 `Deploy from a branch`，分支选 `main`，目录选 `/ (root)`。
4. 等一两分钟，访问：
   - 个人主站：`https://你的用户名.github.io/`
   - 项目页面：`https://你的用户名.github.io/仓库名/`

因为 `index.html` 里读的是相对路径 `content.md`，上面两种部署方式都不用改代码。

### 两个线上注意事项

- **改完内容不会立刻生效**：GitHub Pages 的 CDN 有约 10 分钟缓存。页面里的 `fetch` 已加 `cache: 'no-cache'`，浏览器不会拿旧副本，但 CDN 那一层还是要等一下。
- **Google Fonts 在国内访问不稳定**：页面用 `fonts.googleapis.com` 加载 Noto Serif SC / Noto Sans SC。这个请求被卡住时，因为是渲染阻塞的样式表，首屏可能白屏若干秒才回退到系统字体。如果主要面向国内访问，建议去掉这个 `<link>` 改用系统字体，或把字体自托管到本仓库。

## 其他

- 页面右上角"导出 PDF"按钮会调用浏览器打印功能，方便快速生成一份纸质版简历。
- 页面已做移动端适配，窄屏下时间与内容会自动上下排列。
